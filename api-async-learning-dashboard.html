⏹️ Synchronous vs Asynchronous Code

What's happening: Synchronous code blocks execution (like waiting in line at a coffee shop). Asynchronous code doesn't block (like ordering online). Learn why this matters for web applications.

💡 Key Concept

Synchronous: Code runs line-by-line. Each line waits for the previous one to finish. If one task takes 5 seconds, everything waits.

Asynchronous: Tasks can run in the background. Your code doesn't wait for them to finish.

Try It: Synchronous Code (BLOCKING)

// ❌ BLOCKING - Freezes the page! console.log("Start"); for(let i = 0; i < 5000000000; i++) { // Counting to 5 billion - page FREEZES! } console.log("End");

⚠️ Warning: Click this and notice how the page freezes!

Try It: Asynchronous Code (NON-BLOCKING)

// ✅ NON-BLOCKING - Page stays responsive! console.log("Start"); setTimeout(() => { console.log("Task completed after delay"); }, 2000); console.log("End");

📞 Simple Callback Pattern

What's happening: A callback is a function you pass to another function. The other function runs your callback when the task completes. Like a phone number you give to a restaurant so they can call you when your table is ready.

🎯 The Restaurant Analogy

You: "Call me when my table is ready" (passing callback)
Restaurant: Takes your number and continues seating others
Later: Restaurant calls you (executes callback)
You: Come to restaurant and eat

Code Example: Simple Callback

function greetUser(name, callback) { console.log("Loading user data..."); setTimeout(() => { const userData = { name, id: 123 }; callback(userData); // Call the callback function }, 2000); } function displayUser(user) { console.log("Welcome " + user.name + "!"); } // Pass displayUser as a callback greetUser("Sarah", displayUser);

🔗 The Callback Hell Problem

What's happening: When you nest too many callbacks, code becomes hard to read and maintain. This is why Promises and async/await were invented!

⚠️ The Problem

Multiple nested callbacks create "Pyramid of Doom" - code that's hard to read, debug, and maintain. This is why modern JavaScript moved to Promises and async/await.

❌ Callback Hell Example:

// This is hard to read! getUserData(userId, function(user) { getOrders(user.id, function(orders) { getOrderDetails(orders[0].id, function(details) { calculateTotal(details.items, function(total) { console.log("Total: $" + total); }); }); }); });

✅ The Modern Solution - Promises:

// Much cleaner and easier to read! getUserData(userId) .then(user => getOrders(user.id)) .then(orders => getOrderDetails(orders[0].id)) .then(details => calculateTotal(details.items)) .then(total => console.log("Total: $" + total));

🤝 Promise Basics

What's happening: A Promise represents the eventual result of an async operation. It's like a guarantee: "I'll give you data when it's ready, or tell you what went wrong."

📋 Promise States

Pending: Operation is still running
Resolved (Fulfilled): Operation succeeded - you get the data
Rejected: Operation failed - you get an error

Creating a Simple Promise:

const fetchUser = new Promise((resolve, reject) => { setTimeout(() => { const user = { name: "Alice", id: 1 }; resolve(user); // Success! // OR reject(new Error("Failed!")); }, 2000); }); fetchUser .then(user => console.log("Got user:", user)) .catch(error => console.log("Error:", error));

⛓️ Promise Chaining

What's happening: Chain multiple async operations together. Each .then() waits for the previous one to finish and passes the result to the next.

Chaining Promises:

// Step 1: Get user getUserById(1) // Step 2: Get their orders .then(user => { console.log("User:", user.name); return getOrders(user.id); }) // Step 3: Get order details .then(orders => { console.log("Orders:", orders.length); return getOrderDetails(orders[0].id); }) // Step 4: Display result .then(details => { console.log("Details:", details); }) // Handle any errors .catch(error => { console.log("Error:", error.message); });

📊 Understanding Promise States

What's happening: See how a Promise moves through states: Pending → Resolved OR Pending → Rejected

🔄 The State Lifecycle

1. Pending: Promise created, waiting for result
2a. Resolved: Operation succeeded, .then() runs
2b. Rejected: Operation failed, .catch() runs
Once a promise settles (resolved or rejected), it can't change!

⚡ Async/Await - The Modern Way

What's happening: Async/await is syntactic sugar over Promises. It makes async code look and feel like synchronous code, but it's still non-blocking!

🎯 Key Points

async: Marks a function as asynchronous
await: Pause execution until Promise resolves
Result: Code looks like normal sync code, but is actually async!

Promise vs Async/Await:

// OLD WAY - Promises getUserData(1) .then(user => getOrders(user.id)) .then(orders => console.log(orders)) .catch(err => console.log(err)); // NEW WAY - Async/Await (cleaner!) async function loadData() { try { const user = await getUserData(1); const orders = await getOrders(user.id); console.log(orders); } catch (err) { console.log(err); } }

🔀 Running Operations in Parallel

What's happening: Sometimes you want multiple async operations to run at the same time (parallel), not wait for each one (sequential). Use Promise.all() for this!

⚡ Sequential vs Parallel

Sequential: Task 1 (2s) → Task 2 (2s) = 4 seconds total
Parallel: Task 1 & Task 2 at same time = 2 seconds total
Use parallel when tasks don't depend on each other!

Promise.all() - Run Multiple Promises Together:

// These tasks don't depend on each other async function loadDashboard() { try { // ❌ SLOW - Sequential (4 seconds total) const users = await fetchUsers(); const posts = await fetchPosts(); const comments = await fetchComments(); // ✅ FAST - Parallel (2 seconds total) const [users, posts, comments] = await Promise.all([ fetchUsers(), fetchPosts(), fetchComments() ]); } catch (err) { console.log(err); } }

🌐 Fetch API - Getting Real Data

What's happening: The Fetch API lets you make HTTP requests (GET, POST, etc.) to servers. It returns a Promise, so you can use async/await with it!

📡 How Fetch Works

1. Send request to server
2. Server sends back response
3. Parse response (.json(), .text(), etc.)
4. Use the data in your app

Basic Fetch Request:

// Simple fetch fetch('https://api.example.com/users/1') .then(response => response.json()) .then(data => console.log(data)) .catch(error => console.log(error)); // With async/await async function getUser() { const response = await fetch('https://api.example.com/users/1'); const data = await response.json(); console.log(data); }

❌ Try/Catch Error Handling

What's happening: Try/catch is how you handle errors in async code. Try a block, catch any errors that happen.

🛡️ Error Handling Pattern

try: Code that might throw an error
catch: Runs if an error happens
finally: (optional) Always runs, error or not

Try/Catch with Async/Await:

async function loadData() { try { console.log("Loading..."); const data = await fetchFromAPI(); console.log("Success:", data); } catch (error) { console.log("Error caught:", error.message); } finally { console.log("Cleanup done"); } }

🛡️ Real-World Error Handling

What's happening: Learn common patterns for handling different types of errors in production applications.

Pattern 1: Distinguish Error Types

async function robustFetch(url) { try { const response = await fetch(url); // Check if response is ok if (!response.ok) { throw new Error(`HTTP ${response.status}: ${response.statusText}`); } return await response.json(); } catch (error) { if (error instanceof TypeError) { console.log("Network error:", error.message); } else { console.log("API error:", error.message); } } }

Pattern 2: Retry on Failure

async function fetchWithRetry(url, retries = 3) { for (let i = 0; i < retries; i++) { try { return await fetch(url).then(r => r.json()); } catch (error) { if (i === retries - 1) throw error; console.log(`Retry ${i + 1}...`); await new Promise(resolve => setTimeout(resolve, 1000)); } } }

🔄 Retry Pattern - Try Again on Failure

What's happening: Sometimes network requests fail temporarily. Instead of giving up immediately, try again! This is essential for production apps.

💡 Why Retry?

Network can be flaky. A failed request might succeed on the second try. Don't give up immediately - implement exponential backoff (wait longer each retry).

Retry with Exponential Backoff:

async function fetchWithExponentialBackoff(url, maxRetries = 3) { for (let attempt = 1; attempt <= maxRetries; attempt++) { try { const response = await fetch(url); if (!response.ok) throw new Error(`HTTP ${response.status}`); return await response.json(); } catch (error) { if (attempt === maxRetries) { throw error; // Give up after max retries } // Wait longer each time: 1s, 2s, 4s const delay = Math.pow(2, attempt - 1) * 1000; console.log(`Attempt ${attempt} failed. Retrying in ${delay}ms...`); await new Promise(resolve => setTimeout(resolve, delay)); } } }

⏱️ Timeout Pattern - Don't Wait Forever

What's happening: Sometimes requests hang forever. A timeout stops waiting after a certain time and tells the user something is wrong. Essential for user experience!

⏱️ Why Timeout?

User shouldn't wait forever. Set a reasonable timeout (usually 5-30 seconds). If request takes longer, cancel it and show an error. Better to fail fast than hang forever!

Fetch with Timeout:

async function fetchWithTimeout(url, timeoutMs = 5000) { const controller = new AbortController(); const timeoutId = setTimeout(() => controller.abort(), timeoutMs); try { const response = await fetch(url, { signal: controller.signal }); clearTimeout(timeoutId); return await response.json(); } catch (error) { clearTimeout(timeoutId); if (error.name === 'AbortError') { throw new Error(`Request timed out after ${timeoutMs}ms`); } throw error; } }

🔇 Debounce Pattern - Rate Limiting

What's happening: When users type in a search box, don't fetch data on every keystroke! Wait until they stop typing, then fetch once. This is debouncing - it saves bandwidth and improves performance.

🔍 Real-World Example

User types "j-a-v-a-s-c-r-i-p-t" (10 keystrokes)
Without debounce: 10 API calls ❌
With debounce: 1 API call after 300ms of no typing ✅

Debounce Function:

// Debounce helper function debounce(fn, delayMs) { let timeoutId; return (...args) => { clearTimeout(timeoutId); timeoutId = setTimeout(() => fn(...args), delayMs); }; } // Usage: Search that only runs after user stops typing const searchUsers = debounce(async (query) => { console.log("Searching for:", query); const results = await fetch(`/api/search?q=${query}`); console.log("Results:", results); }, 300); // Each keystroke input.addEventListener('input', (e) => { searchUsers(e.target.value); });
